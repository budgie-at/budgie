# i18n Workflow (Lingui v6)

Budgie uses [Lingui](https://lingui.dev) 6.x in `packages/app` and `packages/landing`.
Catalogs live in `src/i18n/locales/{locale}/messages.{po,ts}` for `en` (source),
`uk`, `fr`, `de`, `es`.

## Daily workflow

1. Write user-facing text with the macros: `<Trans>` for JSX children, `` t`...` ``
   for string props (see AGENTS.md i18n rules).
2. After changing any user-facing text, run in the owning package:
   ```bash
   yarn i18n:sync   # = lingui extract + lingui compile
   ```
3. Commit BOTH `.po` (source) and `.ts` (compiled) — runtime needs the `.ts`.

## Golden rule: never hand-edit catalogs

`.po` and `.ts` files are generated. Do not edit them by hand except to fill in
empty `msgstr ""` translations in `.po`. After filling translations, run
`yarn i18n:sync` to recompile.

## Resolving catalog merge conflicts

Catalogs are marked `linguist-generated` (collapsed in GitHub diffs) and compiled
`.ts` uses `merge=union` (see `.gitattributes`). If git still reports a conflict in
a `.po` or `.ts` catalog:

1. Take EITHER side of the conflict (don't hand-merge): `git checkout --theirs`
   or `git checkout --ours` the conflicted catalog files.
2. Re-run `yarn i18n:sync` in the affected package(s).
3. `git add` the regenerated catalogs and complete the merge/commit.

The regenerated output is authoritative; never resolve catalog conflicts manually.

## Why diffs stay clean

- `format: formatter({ lineNumbers: false })` in `lingui.config.*` drops volatile
  `:LINE` source references, so editing code no longer churns every catalog.
- Message ordering is deterministic (sorted by message id).
- `.gitattributes` marks catalogs generated and union-merges compiled `.ts`.

## Tooling note: `@lingui/format-po` and knip

`@lingui/format-po` is used only inside `lingui.config.*` (by the Lingui CLI at
extract/compile time). knip globally ignores `*.config.*` files, so it cannot trace
that import and would flag the package as unused. It is therefore declared in
`knip.json` → `ignoreDependencies`. This is an accurate tooling-dependency
declaration, not a dead-code suppression.

## Adding a locale

1. Add the code to `locales` in `packages/app/lingui.config.js` and
   `packages/landing/lingui.config.mjs`.
2. For the app, add the pluralrules locale-data import in `packages/app/index.js`
   and load the messages in `packages/app/src/i18n/util/i18n.util.ts`.
3. Run `yarn i18n:sync`, fill the new `.po` `msgstr` entries, re-sync, commit.
